# A1 protected-lane query/binding localization protocol

Status: **frozen for read-only execution**.

This analysis follows the completed protected-lane distance axis. It loads the
verified final checkpoints only and does not train, patch, or save any model
weights. The original A0 and original A1 definitions remain untouched.

## Question

The protected lane preserves its own stored state through distractors but does
not restore held-out retrieval. This diagnostic localizes the break across:

1. value/key storage after the write;
2. persistence through the distractor interval;
3. query-conditioned selection after the query key;
4. integration into the answer-marker output.

The analysis compares the `protected` and `ordinary` lane modes at distances
`0`, `4`, `16`, and `64`. The mode comparison is descriptive; it is not a
new intervention.

## Exact causal positions

The frozen one-binding layout is:

```text
TASK, RECORD, KEY, VALUE, DISTRACTOR×d, QUERY, KEY, ANSWER, VALUE
```

For distance `d`, zero-based positions are:

| Stage | Position | Meaning |
| --- | ---: | --- |
| `post_value` | `3` | The value token has just been processed and the lane has committed. |
| `post_distractor` | `3 + d` | The last distractor, or the value position when `d=0`. |
| `post_query_marker` | `4 + d` | The query marker has been processed. |
| `post_query_key` | `5 + d` | The query key has been processed; this is the primary post-query stage. |
| `answer_marker` | `6 + d` | The native lane read and answer-marker output representation are available. |

The four primary report stages are `post_value`, `post_distractor`,
`post_query_key`, and `answer_marker`. `post_query_marker` is retained as an
auxiliary stage because it separates the marker transformation from query-key
processing.

## Captured representations

For every example and stage, the read-only forward pass records:

- base A1 hidden state before lane delta;
- final normalized answer representation after lane delta;
- projected key and value candidates;
- protected/ordinary lane `memory_key` and `memory_value`;
- query-key candidate used by the lane at the answer marker;
- similarity, read gate, and lane delta;
- native logits and counterfactual base-only logits at the answer marker.

The counterfactual base-only logits are computed from the same frozen base
hidden state with the lane delta omitted. They are diagnostic arithmetic, not a
model intervention and not a production prediction.

## Predeclared probes and metrics

All probes are temporary ridge readouts and are discarded after the analysis.
They do not change model parameters.

### Identity and transfer probes

For key and value identity, fit a linear readout to the corresponding frozen
token-embedding vector on the training split and evaluate it on the held-out
split. Report top-1, top-5, target rank, and target cosine over the candidate
pool. The value pool is the full 8,000-value range. The key pool is the union
of the fixed train and held-out key ranges.

The fixed `post_value` probe is evaluated at every later stage. This is the
primary same-coordinate persistence test. A four-fold held-out-only probe is
also fit separately at each stage to measure local decodability without
claiming cross-example transfer.

### Binding and query-conditioned probes

At each stage, report three progressively richer value readouts:

- `value_only`: lane `memory_value`;
- `pair_state`: concatenated `memory_key` and `memory_value`;
- `query_conditioned`: concatenated query-key candidate, `memory_key`, and
  `memory_value`.

Each predicts the target value embedding and is evaluated against the full
value pool. The comparison is deliberately diagnostic rather than a claim
that a one-association probe proves a complete relational algorithm:

- value identity without a joint/query-conditioned gain means the value trace
  is present but key-conditioned selection is weak;
- a joint or query-conditioned gain means the frozen state contains usable
  binding information even if native output does not use it;
- no cross-split value signal means the required transferable code is absent or
  has changed coordinates.

Query identity is probed from the query-key candidate and base hidden state
against the key-token pool. The local held-out probe is the primary query
identity measure because the fixed train and held-out keys are disjoint.

### Native output and output integration

At the answer marker, report full-vocabulary and value-range cross-entropy,
top-1 accuracy, target probability, target-vs-best-incorrect margin, and target
rank for native logits and base-only logits. Also report the target-logit and
rank change caused by adding the frozen lane delta.

Finally, fit a diagnostic value readout from the final normalized answer
representation. A strong diagnostic value readout with weak native output is
classified as an output routing/integration gap; weak diagnostic and native
output are classified as an upstream representation/binding gap.

## Predeclared adjudication rules

- Value identity drops from `post_value` to `post_distractor` in the fixed
  probe: distractor-state corruption/storage loss remains supported.
- Value identity survives `post_distractor` but drops after `post_query_key`:
  query-conditioned transformation is supported.
- Value identity survives the query, but query-conditioned/pair probes fail:
  binding or associative addressing is supported.
- Query-conditioned/pair probes are strong at the answer marker but native
  output is weak: downstream readout/routing is supported.
- Native and diagnostic representations both fail before the query: formation
  or recurrent-state transformation is supported.
- Protected and ordinary modes show the same localization: persistence
  protection is not sufficient to change the downstream bottleneck.

These are localization rules, not causal claims. No training intervention is
unlocked by this read-only analysis. A new inference-time intervention would
require a separately frozen protocol.
